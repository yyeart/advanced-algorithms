## Counting sort: первое упражнение

Для ключей `0..K` заведи `K + 1` счётчиков. Время — `O(n + K + 1)`, дополнительная память устойчивой реализации — `O(n + K + 1)`. Это следствие проходов по входу, счётчикам и выходу: [MIT, лекция 7](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-fall-2011/7392afcfcced991eeb067c822e9ace04_Nz1KZXbghj8.pdf).

Учебный вход: `a = [2, 0, 2, 1]`, `K = 2`.

```text
индекс ключа:       0  1  2
частоты:           1  1  2
префиксные суммы:  1  2  4
```

Числа рассчитаны подсчётом элементов исходного массива и последовательным сложением частот. Сумма для ключа 2 равна 4: всего четыре элемента не больше 2. Значит, последний элемент с ключом 2 должен стоять на индексе 3.

Размещение справа налево:

```text
1 -> --count[1] = 1 -> b[1] = 1
2 -> --count[2] = 3 -> b[3] = 2
0 -> --count[0] = 0 -> b[0] = 0
2 -> --count[2] = 2 -> b[2] = 2
результат: [0, 1, 2, 2]
```

Устойчивость означает сохранение исходного порядка записей с равными ключами. Для `(2,A), (1,B), (2,C)` результат — `(1,B), (2,A), (2,C)`. Обратный обход с уменьшением конца группы сохраняет этот порядок. При этой формуле размещения обход слева направо его нарушит: [учебный разбор Университета Сан-Паулу](https://www.ime.usp.br/~pf/algorithms/chapters/radixsort.html).

Если нужны только числа, можно восстановить их из частот. Но так нельзя восстановить сопутствующие значения записей. Для radix используй вариант с выходным буфером: [Open Data Structures](https://opendatastructures.org/ods-java/11_2_Counting_Sort_Radix_So.html).

Файл [01_counting.cpp](/Users/yyeart/VSCode/sem3/discran/public/linear_sort_prep/01_counting.cpp) содержит полную программу. Запуск из папки `public`:

## Radix sort: меняется ключ одного прохода

LSD означает обработку от младшего разряда к старшему. Каждый проход должен быть устойчивым, чтобы сохранить порядок по уже обработанным разрядам: [Open Data Structures](https://opendatastructures.org/ods-java/11_2_Counting_Sort_Radix_So.html).

В [02_radix_numbers.cpp](/Users/yyeart/VSCode/sem3/discran/public/linear_sort_prep/02_radix_numbers.cpp) ключ прохода — `(a[i] / exp) % 10`, где `exp` последовательно равен 1, 10, 100. Например:

```text
вход:        21 11 12
по единицам: 21 11 12
по десяткам: 11 12 21
```

Это вычислено по цифрам исходных чисел. Если переставить 11 и 12 на втором проходе, результат окажется неверным. Поэтому недостаточно просто собрать числа по очередной цифре в любом порядке.

При `d` разрядах и основании `B` время — `O(d(n + B))`: `d` проходов по `n` элементам и `B` счётчикам. Здесь `B = 10`. «Линейная» не означает, что количество разрядов всегда можно игнорировать: [Open Data Structures](https://opendatastructures.org/ods-java/11_2_Counting_Sort_Radix_So.html).

Пример 02 принимает только неотрицательные числа. Пример [03_radix_records.cpp](/Users/yyeart/VSCode/sem3/discran/public/linear_sort_prep/03_radix_records.cpp) поддерживает ключи от −10^9 до 10^9, прибавляя 10^9 перед извлечением цифры; получается диапазон 0..2·10^9. Прибавление одной константы сохраняет порядок, поскольку `x < y` равносильно `x + c < y + c`. Это преобразование ключа, исходные поля не меняются.

Для ключа и значения нужен контейнер записей, например:

```cpp
struct Record {
    int key;
    string value;
};
```

Счётчик выбирается по `a[i].key`, в буфер переносится **вся** `a[i]`. Если в условии дан класс, посмотри, как получить ключ: через открытое поле или предоставленный метод. В `struct` поля открыты по умолчанию; в `class` — закрыты: [проект стандарта, class.access.general](https://eel.is/c++draft/class.access.general). Нового алгоритма для класса не требуется: меняется доступ к ключу и тип элемента.

В примерах 03 и 04 `std::move(a[i])` используется при передаче записи/строки в буфер. Ключ вычисляется до этого действия. Размещение присваиванием `b[...] = a[i]` также корректно, но копирование длинных строк добавляет стоимость; для оценки времени нельзя считать такое копирование константным: [проект стандарта, string assignment](https://eel.is/c++draft/string.cons).

Дополнительная тренировка: сортировка по двум полям. Для лексикографического порядка устойчиво отсортировать сначала по второму полю, затем по первому. Последний проход задаёт главный ключ, предыдущий — порядок при равенстве главного: [Сан-Паулу, radix sort](https://www.ime.usp.br/~pf/algorithms/chapters/radixsort.html).

## Строки

В [04_radix_strings.cpp](/Users/yyeart/VSCode/sem3/discran/public/linear_sort_prep/04_radix_strings.cpp) рассматриваются только строчные латинские буквы в ASCII. Позиции обрабатываются от последней к первой, каждая — устойчивым counting sort. Для строк одной длины это обычный LSD; для разных длин отсутствующий символ считается меньше любой буквы: [Princeton, String Sorts Study Guide](https://www.cs.princeton.edu/courses/archive/fall14/cos226/lectures/study/51StringSorts.html).

В коде конец строки получает ключ 0, буквы — 1..26, всего 27 счётчиков. Пример проверки: `ab, a, aa, b` должен дать `a, aa, ab, b`. Это лексикографическое сравнение: при совпадении префикса более короткая строка раньше.

При максимальной длине `L` схема делает `L` проходов: `O(L(n + A))` операций с элементами и счётчиками для алфавита размера `A`, при постоянной стоимости получения символа и переноса элемента. Длинные строки и стоимость их копирования следует учитывать отдельно: [Princeton, LSD implementation](https://algs4.cs.princeton.edu/code/edu/princeton/cs/algs4/LSD.java.html), [проект стандарта](https://eel.is/c++draft/string.cons).

Если задача требует **только последние k символов строк длины m**, выполняй проходы по позициям `m - 1` до `m - k` включительно. Остальные позиции обрабатывать нельзя: это уже другая требуемая сортировка. Такая адаптация следует из цикла LSD и заданных позиций ключа. Проверять нужно именно порядок по суффиксу, а не по всей строке.

MSD начинает со старшего символа и продолжает отдельно внутри полученных групп. При нехватке времени я рекомендую сначала освоить LSD; наличие MSD в конкретном контесте неизвестно. Различие вариантов: [Princeton, String Sorts](https://algs4.cs.princeton.edu/51radix/).

Этот пример не сортирует русский текст, UTF-8 или смешанный алфавит. Программа читает непустые слова через `cin >>`; сама функция с ключом конца строки способна обработать пустую строку в уже созданном векторе.

## Bucket sort

В [05_bucket.cpp](/Users/yyeart/VSCode/sem3/discran/public/linear_sort_prep/05_bucket.cpp) вход ограничен диапазоном `[0, 1)`. Для `n` элементов создаётся `n` корзин; номер корзины — целая часть `x*n`. Каждая корзина сортируется вставками, затем корзины соединяются по возрастанию номера: [лекция Университета Нью-Мексико](https://www.cs.unm.edu/~saia/classes/561-f07/lec/lec7-2x2.pdf).

Для четырёх корзин: `0.12 -> 0`, `0.77 -> 3`, `0.31 -> 1`, `0.25 -> 1`. Индексы рассчитаны как `floor(4*x)`. В корзине 1 порядок `[0.31, 0.25]` нужно исправить на `[0.25, 0.31]`. Одного распределения недостаточно.

При независимом равномерном распределении и `n` корзинах ожидаемое время этой схемы — `O(n)`. Если все элементы попали в одну корзину, внутри неё возможна квадратичная работа вставок; худшее время — `O(n²)`. Память — `O(n)`. Название темы «линейные сортировки» не даёт bucket sort безусловную линейную гарантию: [лекция UNM](https://www.cs.unm.edu/~saia/classes/561-f07/lec/lec7-2x2.pdf), [Princeton, упражнение о равномерном распределении](https://algs4.cs.princeton.edu/51radix/).

Для другого диапазона требуется другая формула корзины. Не отправляй этот пример в задачу с произвольными целыми числами без адаптации. Внутри корзин готовая сортировка не используется.

## Перед отправкой решения

Сверить с условием: диапазон ключей, наличие отрицательных чисел, алфавит, длины строк, полный ключ или только суффикс, требуемую устойчивость, формат ввода и вывода, память и версию C++.

Самопроверка: объяснить, что значит `count[x]` до и после префиксных сумм; почему вычитаем 1 перед размещением; почему идём справа налево; почему radix переносит элемент целиком; что происходит с одинаковыми ключами. Затем написать counting sort без просмотра образца.

Не выделять массив счётчиков размером в миллиард ради ключей до миллиарда. Количество счётчиков равно размеру диапазона; radix в наших числовых примерах использует 10 на проход. Для отрицательных ключей в counting sort можно использовать индекс `x - minimum`, но размер `maximum - minimum + 1` и арифметику надо проверить по ограничениям задачи.
